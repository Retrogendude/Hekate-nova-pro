### DIAGNOSTIC-INTEGRATION.md

# Hekate 6.5.4 — Diagnostic tab, prototype 1

Update: this archive also includes presentation prototype 2.
See `INTERFACE-CONSOLE.md` for the interface changes, the fix for reading
the DRAM channels and the validation limits.

This working version adds a Diagnostic tab to Nyx. The tests run directly in Nyx, without launching HWTest-RCM separately.

Integrated from HWTest-RCM 0.15: screen identification, LCD/OLED backlight status, DRAM identification and channel comparison. Textual PASS/WARN/FAIL results. The probe sources are kept in frontend/diagnostics, with a dedicated Nyx adapter.

Not integrated: power, storage, audio, Wi-Fi/Bluetooth, input diagnostics, full RAM test, report export. The DRAM test present identifies the memory; it does not check all of its cells.

The tab is added after Options in order to preserve the indices of the existing tabs. No test runs when the tab is opened.

Build: use the Hekate procedure with devkitARM, then build Nyx via its Makefile (from nyx: make). No compiled binary is provided. The ARM build tools are not available in the environment used; neither the build, nor the display on console, nor the hardware measurements have been validated. This prototype is intended for review and a build before any installation.

Points to check on hardware: width of the six tabs, opening/closing of results, repeated runs, LCD/OLED diagnostics, Erista/Mariko DRAM identification. The verdicts are observations of the registers and do not constitute a complete validation of the hardware.

Provenance: user archives hekate-6.5.4.zip and HWTest-RCM-0.15.zip. Hekate licence kept in LICENSE. The provenance comments of the HWTest-RCM probes are kept. The HWTest-RCM archive provided does not contain an identified root licence; check the redistribution rights of its probes before public distribution.


### INTERFACE-CONSOLE.md

# Hekate 6.5.4 — console interface, prototype 2

The Nyx home screen now uses four large coloured tiles: Launch,
Configs, Payloads and emuMMC. Each tile presents a title and a
description. Two shortcuts give access to Diagnostic and to the Nyx settings.
The reload, restart and power-off buttons keep their actions and
their existing dialogs.

The Diagnostic tab reuses these colours and offers three choices: summary of the
integrated checks, screen, memory identification. The results display
the number of failures and warnings as well as the details of the observations.
The available tests remain those of the first prototype; this version
does not add the audio, radio, storage or full RAM tests.

## Scope

- Home screen and Diagnostic reworked; main navigation shortened and
  partially translated. The existing secondary windows are kept.
- Native layout for the 1280 × 720 screen; no additional image or font
  to load onto the SD card.
- Opaque tiles, rounded corners and a visual indication on press. The custom
  background remains visible around the tiles.
- French labels without accents in the native sources: the current
  embedded fonts only cover ASCII. The design mockup
  may display accents and icons that differ from the native symbols.
- Internal order of the tabs preserved: Options = 4, Diagnostic = 5.
- Choosing between main and additional configs uses an
  explicit identifier, instead of relying on the text displayed on the button.

## Fix associated with the diagnostic

Four extractions of the second byte of the memory registers in
`bdk/mem/sdram.c` had an operator precedence problem:
`mrr & 0xFF00 >> 8`. They now use `(mrr & 0xFF00) >> 8`.
This fix makes it possible to distinguish the two channels instead of reusing
the first byte for both. The eight extraction expressions were
verified with four words containing distinct bytes, i.e. 32 successful cases.

## Checks and limits

The navigation calls, the indices of the six tabs, the dimensions of the
tiles and the widths of the titles were examined from the sources and
the metrics of the embedded fonts. The JavaScript syntax of the interactive
mockup was checked. The browser did not authorise opening it
from a local file; no browser rendering was validated here.

The ARM build chain is not installed in this environment.
No build, no binary and no hardware trial are provided.
The mockup presents a visual direction; it runs no test and
is not a capture of the program running on console.

Before installation, build Hekate and Nyx with devkitARM following the
project Makefiles, then check on console access to the six tabs,
the actions of each tile, the results windows, repeated calls,
DRAM reading on Erista/Mariko and the LCD/OLED panels.

See also `DIAGNOSTIC-INTEGRATION.md` for the scope and provenance
of the HWTest-RCM probes.
