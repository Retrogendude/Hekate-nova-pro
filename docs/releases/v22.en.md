# Hekate Nova Pro 22

Updated functional base: Hekate 6.5.5 / Nyx 1.9.5, with the Nova style.
This version fixes the erroneous Nyx warning and several possible blockages
of the wireless commands. The Bluetooth link remains experimental.

## Install

1. Keep a copy of your current bootloader folder.
2. Copy the provided bootloader folder to the root of the SD card and accept
   the replacement of the files. It is not necessary to delete the folder.
3. Inject hekate_nova_pro_6.5.5_v22.bin, or use the provided bootloader/update.bin.
4. Check "22" in the credits and "Hekate 6.5.5 / Nyx 1.9.5".

The personal nyx.ini and hekate_ipl.ini files are not provided in this
package. Your settings, themes, backgrounds, fonts and boot configurations are
kept. Replacing only the payload without updating nyx.bin is not enough.

## "Old Nyx GUI found" warning

The delivered v21 placed the Nyx metadata at a wrong position in the binary.
This triggered a false warning even when all the right files were
present. The Nyx entry is now isolated, and the build is refused if
the placement of the metadata changes. The compatibility check of Hekate remains
active: a real mix of versions can still trigger this warning.

## Hekate / Nyx update

The official changes relating to HOS 23.5.0 are incorporated into the core of Nova,
with the NOGC fix for FAT32 published after the 6.5.5 tag. The panels, icons,
colours and Nova layouts remain those of the previous version.

The emuMMC module and the L4T component sc7exit_b01.bin come from the official updated
6.5.5 package whose checksum was checked. Nyx and the payload remain the Nova
binaries compiled for this version, and are not replaced by the official
interface. The Nova resources and the diagnostics are kept.

## Wireless Joy-Con

In Nyx Settings → TV / Dock → Wireless Joy-Con:

1. Attach the Joy-Con already paired to this console, then choose Read the pairings.
2. Check the number imported, detach the Joy-Con and choose Enable Bluetooth.
3. Wake the Joy-Con with a button, leave the sticks at rest for a moment,
   then move the stick and check A / ZL / ZR.

The keys remain in memory during the session. They are not written to the SD
and the pairings stored in the Joy-Con are not modified. The service remains
disabled at each startup. It is stopped before the diagnostics, the USB mode and
the launch of another system; relaunch it manually after a diagnostic.

Navigation fixes:
- If the chosen side is absent, the stick of the other connected Joy-Con can drive
  the cursor. The saved setting of the preferred side is kept.
- A / ZL / ZR wake the hidden cursor and remain usable during the centring.
- The simple 0x3F reports are decoded, in addition to 0x21 and 0x30. The confirmation
  of the full mode is tracked, and the old commands are released.

The HCI counters alone do not prove that the buttons are received. An additional
status line now makes it possible to distinguish:

| Field | Reading |
| --- | --- |
| Joy-Con reports | Number of reports actually decoded, left / right |
| ID | Report type, generally 30 in full mode, 3F in simple mode |
| HID | 1 when the controller connection is open |
| ACK | 1 when the full mode is confirmed or a 30 report is received |
| ERR | Last failure code of the connection opening, 00 when no error is recorded |
| BTN | Buttons decoded; the value must change during a press |
| XY | Stick values; about 2048,2048 at rest in full mode |

If the commands still do not respond, record this line while holding A,
then while moving the stick. This makes it possible to separate a connection, decoding
and navigation problem. No failure of the prototype is by itself a
diagnosis of hardware failure.

## Checks and limits

The ARM build, the positions and versions of the headers, the real decoding /
merging / pointer paths up to the LVGL click, the menus and the TV regressions
are checked on PC with substituted hardware inputs. Two navigation
blockages were reproduced on the v21 code before checking the fixes.
The verification program also refuses a Nyx entry that shifts the header.

A physical validation of this v22 on your console remains necessary: the PC
tests do not prove a radio connection, a HOS startup or a real HDMI output.
The settings of the video driver and the dock detection remain those of Nova v20/v21.
