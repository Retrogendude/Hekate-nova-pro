# Hekate Nova Pro 24 — fix for the Joy-Con key import

Base: Hekate 6.5.5 / Nyx 1.9.5. Nova interface and settings kept.

The v23 report showed an authentication refusal 05 and no ACL exchange.
An error has been identified in Nova: a second byte inversion of the
key already prepared by Hekate. It is removed in this version.
The comparison with the Switchroot import path is described in
AUTH-SOURCES-V24.md. The key type and the security are kept.

The build and the software tests pass. The operation of the wireless commands
still has to be confirmed on a console.

## Installation and trial

1. Copy the contents of the archive to the root of the SD, replacing the files
   of the **bootloader** folder. The settings files are not provided.
2. Use the payload **hekate_nova_pro_6.5.5_v24.bin** if necessary.
3. Restart the console completely. In Nyx, open **Settings → TV / Dock →
   Wireless Joy-Con**.
4. Attach both Joy-Con and choose **Read the pairings**.
5. Detach the Joy-Con, choose **Enable Bluetooth**, then press a button.
6. Check that HID and Reports increase, then try the stick and A / ZL / ZR.
7. Choose **Stop Bluetooth** to record the new report:
   `bootloader/bluetooth/last-session.txt`.

The pairings have to be read again after the restart: the keys remain only
in memory. It is not necessary to delete the settings or the existing
pairings. The service does not create a new pairing.

The report adds **HOST=1** when the re-read Bluetooth identity corresponds to
the expected one. **HOST=2 / error 9** signals a different identity and interrupts
the connection. **AUTH=05** indicates an authentication refusal; **AUTH=00** is
a success only if an authentication event has actually taken place
(visible in the trace). HID and Reports remain the indicators of the commands.
The keys, addresses and raw packet contents are never logged.

The previous fixes for the Nyx header, the dock and the diagnostics are
kept. BTstack keeps its distinct personal/non-commercial licence,
included in the package documentation.
