# Hekate Nova Pro25 — Joy-Con reconnection trial

Base kept: Hekate6.5.5 / Nyx1.9.5. Nova interface and settings kept.

The v24 report confirms a successful authentication for one connection, then
a loss of link during the activation of the encryption (08). The fix
of the key format of v24 is kept. A connection problem remains.

This version requires the console to take the main role when a Joy-Con
initiates the reconnection, and launches the outgoing attempts successively.
These changes are checked on PC. Their effectiveness on the console remains
to be confirmed: the report alone does not allow attributing with certainty the
cut to the Bluetooth role.

## Install and try

1. Copy the contents of the ZIP to the root of the SD, replacing the files
   of the **bootloader** folder. The settings files are not provided.
2. Use **hekate_nova_pro_6.5.5_v25.bin** if necessary, then restart
   the console completely.
3. Open **Settings → TV / Dock → Wireless Joy-Con**. Attach the Joy-Con,
   choose **Read the pairings**, then detach them and enable Bluetooth.
4. Press a button to wake them and try the buttons/sticks.
5. Choose **Stop Bluetooth** after the trial. The report is located in
   `bootloader/bluetooth/last-session.txt`.

Do not use only the state of the LEDs as a criterion: the counters of
reports and the operation of the commands are the useful indicators.
The keys remain in memory and must be read again after each restart.

## New report

- AUTH=00 SEEN=1: an event confirms a successful authentication.
- ENC=00 SEEN=1 ENABLED=1 or2: encryption activated as long as the link is active.
- ENC=08 SEEN=1: the link expired during this step.
- DISC: disconnection reason kept.
- ROLE=00: main role known to the stack; 01: secondary; FF: unknown.
  The role changes received appear in trace13; the policy
  requested at acceptance appears in trace14.
- HOST=1: controller identity matching that of the imported pairings.
- SEEN=0: no corresponding event observed; 00 alone does not prove a success.

The last results remain available after Stop, even if it is pressed
a second time. The next Bluetooth startup opens a new session.
The report includes the controller version, without addresses, keys or raw packets.

The link security is kept. No new pairing and no key writing
are carried out. The previous Nyx, dock and diagnostic fixes are
kept. The specific licence of BTstack is included in the documentation.
