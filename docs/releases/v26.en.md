# Hekate Nova Pro26 — fix for the simultaneous openings of the Joy-Con channels

Base kept: Hekate6.5.5 / Nyx1.9.5. Nova interface and settings kept.

Your v25 report confirms successful authentications and encryption activations,
as well as the first ACL exchanges. The following blockage is visible:
Nova and the Joy-Con request the opening of the controller channel simultaneously, then
Nova refuses the incoming request with 0004. No button report arrives.

v26 accepts the incoming request when an outgoing attempt is still
pending. It keeps the same controller session and isolates the late replies of
the old attempt. The duplicates are checked and the old channels cleaned.
The security, the key format and the main role setting are kept.

The refusal was reproduced on PC with the v25 code. The v26 tests pass for the
simultaneous openings, the commands, the duplicates, the late replies and the
cleaning. The real operation remains to be confirmed on your console.

## Install and try

1. Copy the contents of the ZIP to the root of the SD, replacing the files of the
   **bootloader** folder. The settings files are not provided.
2. Use **hekate_nova_pro_6.5.5_v26.bin** if necessary, then restart
   completely.
3. Open **Settings → TV / Dock → Wireless Joy-Con**. Attach the Joy-Con and
   choose **Read the pairings**.
4. Detach the Joy-Con, enable Bluetooth and press a button to wake them
   up. Try the sticks and the buttons A / ZL / ZR.
5. Choose **Stop Bluetooth** after the trial. The report remains saved in
   `bootloader/bluetooth/last-session.txt`.

The **Reports**, **ACK** counters and the commands actually received are
the useful indicators. After the stop, HID and ENABLED may be 0: the
service is cut. The counters and the last events remain kept.
SEEN=1 indicates that an event has been observed; 00 with SEEN=0 does not prove a
success. The addresses, keys and raw packet contents are not recorded.

The next Bluetooth startup resets the session report to zero. The
keys remain in memory; they have to be read again after a restart.
