# Hekate 6.5.4 — Diagnostic tab, prototype 1

Update: this archive offers two home screens in prototype 4.
See `INTERFACE-ACCUEIL.md` for the interface changes and the validation
limits. The fix for reading the DRAM channels is retained:
the four expressions `(mrr & 0xFF00 >> 8)` now use
`((mrr & 0xFF00) >> 8)` to read the second byte rather than the first.

This working version adds a Diagnostic tab to Nyx. The tests run directly in Nyx, without launching HWTest-RCM separately.

Integrated from HWTest-RCM 0.15: screen identification, LCD/OLED backlight status, DRAM identification and channel comparison. Textual PASS/WARN/FAIL results. The probe sources are kept in frontend/diagnostics, with a dedicated Nyx adapter.

Not integrated: power, storage, audio, Wi-Fi/Bluetooth, input diagnostics, full RAM test, report export. The DRAM test present identifies the memory; it does not check all of its cells.

The tab is added after Options in order to preserve the indices of the existing tabs. No test runs when the tab is opened.

Build: use the Hekate procedure with devkitARM, then build Nyx via its Makefile (from nyx: make). No compiled binary is provided. The ARM build tools are not available in the environment used; neither the build, nor the display on console, nor the hardware measurements have been validated. This prototype is intended for review and a build before any installation.

Points to check on hardware: width of the six tabs, opening/closing of results, repeated runs, LCD/OLED diagnostics, Erista/Mariko DRAM identification. The verdicts are observations of the registers and do not constitute a complete validation of the hardware.

Provenance: user archives hekate-6.5.4.zip and HWTest-RCM-0.15.zip. Hekate licence kept in LICENSE. The provenance comments of the HWTest-RCM probes are kept. The HWTest-RCM archive provided does not contain an identified root licence; check the redistribution rights of its probes before public distribution.


### INTERFACE-ACCUEIL.md

# Hekate 6.5.4 — two home screen layouts, prototype 4

This version integrates two layouts of the Nyx home screen, selectable
in the settings. The Hekate functions and the new Diagnostic tab remain
accessible in both modes.

## Choosing the layout

1. Open the Nyx settings from the home screen.
2. Use the “Disposition” button at the top of the Nyx settings.
3. Choose “Tuiles” or “Carrousel”.
4. Use “Save and reload” to apply the choice.

Closing the selector without saving keeps the previous layout.
The choice is stored in the `[config]` section of `bootloader/nyx.ini`:

```ini
home_layout=0
```

`0` selects the tiles and `1` the carousel. A missing or invalid setting
uses the tiles. The existing `homescreen` setting remains independent:
to display the home screen at startup, choose “Main menu” in “Home Screen”.

## The two modes

**Tuiles** (Tiles): a large launch command and four accesses to the additional
configs, payloads, emuMMC management and Diagnostic.

**Carrousel** (Carousel): cards move within a horizontal area. The arrows
or a visible card change the selection; “Ouvrir” (Open) launches only the
chosen function. A selection never launches a payload automatically.
The mode does not promise direct navigation with the directional pad:
the Joy-Con keep the pointer behaviour already present in Nyx.

Both modes use native shapes and fonts, with no additional images
to place on the SD card. The French labels of the sources
use ASCII compatible with the embedded fonts.

## Saving and diagnostic

The selector checks that Nyx is present before reloading. A save
error must display a message and prevent the reload. Errors in
writing and closing the configuration file are now taken
into account by the Nyx configuration writer.

The available Diagnostic checks remain screen identification,
backlight status and DRAM identification. Audio, radios,
storage and the full RAM test are not integrated. The DRAM channel
reading fix from the previous prototype is retained.

## Validation and limits

This delivery contains the sources only. The ARM build chain
is not installed in the environment used; no compiled binary
and no trial on console is provided. The interactive mockup presents the choice
in the settings and does not read or write a real SD card.

Before installation, build Hekate and Nyx with the chain intended by their
Makefiles, then check the two layouts on the 1280 × 720 screen,
the shortcuts, the settings, the retention of the choice after reload,
cancellation, write errors and touch/Joy-Con navigation.

See `DIAGNOSTIC-INTEGRATION.md` for the provenance and scope of the probes.
