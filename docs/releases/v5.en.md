Complete build succeeded on 4 November 2026 from the project Makefiles.

- ARM target: devkitARM GCC 16.1.0 installed by devkitPro.
- Windows tools: GCC 16.2.0, GNU Make 4.4.1 and the BusyBox shell of w64devkit 2.11.0.
- The w64devkit archive was obtained from the official skeeto/w64devkit repository and
  its SHA-256 was verified against the GitHub release metadata.
- MSYS2 could not create its signal channel in the execution environment.
  The build used the portable Windows tools and a local copy of
  `base_tools` without the MSYS2-specific PATH rewriting. The Makefiles,
  ARM compilation options and link scripts of the project are kept.
- No additional software was installed into devkitPro by the build.

Results: uncompressed Hekate 134,529 bytes (limit 140,288), final payload
110,204 bytes (limit 126,296), Nyx 610,941 bytes. The separate RAM service is 75,548 bytes (limit 130,392) and its
decompressed image 174,092 bytes. The limits are checked
on the final files, including the six-byte suffix of the payload.

The ARM outputs are ELF32 ARM EABI5, with entry points 0x40007000
(loader) and 0x81000000 (Nyx). The binary files of the loader and of Nyx
were checked against the linked ELFs; the payload carries the suffix ICTC49.

The compiler emitted non-blocking warnings for unused LVGL variables,
an old button function that has become unused and
the RWX link segments of the embedded programs. GNU Make also reports
the resetting of parallelism in the sub-builds.

The settings save passed 69 C cases on the real functions extracted
from the sources, with SD card stubs: modes 0/1, invalid values,
retention of the old settings and mount, open, write and
close failures. This does not replace hardware trials.

The package contains the unchanged precompiled resources of the official
Hekate 6.5.4 / Nyx 1.9.4 release, as well as the newly built
custom binaries. Their provenance and checksums appear in
BUILD-INFO.json next to the instructions of the binary package.

To rebuild in a working devkitPro/MSYS2 environment with a native GCC
available, the standard command remains `make -j4` at the project root.

## Complete integration of prototype 5

The 8,128-byte AArch64 Wi-Fi program is included and required for the build.
The native table contains the 42 HWTest-RCM entries. The RAM service uses the exact
Atmosphère revision indicated in DEPENDENCIES.json and keeps a
Hekate return image in the area already excluded from the first 4 MiB of DRAM.

Additional checks on the real code: 108 assertions of the bounded
payload reader; bounded capture and ten export cases; six summary cases
with missing keys, partial success, warnings and faults; 28 cases of the
RAM/return contract. The C decoder of the loader reconstructs all the bytes of
the decompressed RAM image. None of these checks simulates the physical
measurements of the console's peripherals.

The sources of the RAM companion and its required dependencies are provided
with the Hekate sources. On a system with devkitARM, devkitA64,
Python 3, Git, native GCC and Make, build Hekate at its root, then the RAM
service in HWTest-RCM-0.15/ramtest. The Windows scripts under build-tools are
references for the portable environment used in this session.


### DIAGNOSTIC-INTEGRATION.md

# Hardware diagnostic — native integration, prototype 5

The 42 entries of the HWTest-RCM 0.15 table are integrated into Nyx: identity,
fuses and KFUSE; power, charging, battery and thermal; memory and
clocks; SD, eMMC, partitions, GPT, PRODINFO and cartridge reader;
Bluetooth, Wi-Fi and CPU complex; codec, clocks and audio outputs; screen
and backlight; touch, ambient light, Joy-Con and buttons; GPIO,
UART, restart cause and PMC registers; summary and cross-checks.

The Diagnostic tab offers a summary, ten categories and the isolated RAM service.
Each category allows a collective execution or probe by probe. The
results distinguish OK, warning, fault, error, observation and not
executed. An absence of measurement or prerequisite does not become a success.
The reports can be viewed by pages then exported to the SD card
under `bootloader/diagnostics/hwtest_XXXXXXXX.txt`, without re-running the measurements.
The capture is bounded to 256 KiB with an explicit marker in case of truncation.

## Adaptation to Nyx

The probes are present under `nyx/nyx_gui/diagnostics/vendor/`. The main
program, the interface and the on-screen/UART logging of the original payload
are not used: a native adapter captures the report and publishes the
progress in the Nyx windows. The command driver and the maintenance
tasks are suspended during the measurements then restored. The data,
GPIO/pad states, fan, audio, PCIe, eMMC partition and modified key slots
are restored when their access is available. Reactivating the
touch uses the path without persistent auto-calibration.

The Wi-Fi genuinely includes the required AArch64 CPU0 program: the build fails
if this program is not available. It reserves A0000000..A003FFFF, outside
the Nyx heap and the screen images. The diagnostic messages are never
sent on the UART-B used by the right Joy-Con.

## Prerequisites and interpretation

Some measurements depend on the model or on the components present. Decrypted
PRODINFO reads require `switch/prod.keys` of this console and readable/writable
SE slots; otherwise they are reported as not
performed or with a warning, without overwriting Nyx's locked keys.
The sound test plays the outputs in succession and must be checked by listening.
A verdict of the audio transport does not prove that the speaker is audible.

## Separate RAM and return to Hekate

`bootloader/sys/hwtest_ram.bin` is a separate program: Nyx is exited so as
not to keep an interface in the memory subjected to the tests. The service
runs a single sequence of the seven advanced patterns on all accessible and
unreserved areas, then reloads Hekate. The return forces the menu and
a new instance of Nyx displays the retained result, including after
cancellation or failure of the test. The first 4 MiB, including the return image and its
header, remain excluded. A corrupted return image is never executed;
a hardware failure or a controller hang may prevent any return.

The size of both images is checked before allocation, and short or
failed reads are rejected. The return image
comes from `bootloader/update.bin`, is recognised as Hekate, bounded to 128 KiB and
checked by checksum before use. The RAM service is bounded to 130392
bytes. The shared contract and its copy are verified identical.

## Validation

ARM build of Hekate/Nyx, AArch64 Wi-Fi program and RAM service succeeded.
C tests on real functions: configuration save, bounded reads,
capture/export and partial verdict, RAM return contract. The decompression of the
service is verified by the real C decoder and the binaries are compared with the
linked ELFs. No trial on console and no physical validation of the measurements has yet
been carried out.

### INTERFACE-ACCUEIL.md

# Hekate 6.5.4 — two home screen layouts, prototype 5

This version integrates two layouts of the Nyx home screen, selectable
in the settings. The Hekate functions and the new Diagnostic tab remain
accessible in both modes.

## Choosing the layout

1. Open the Nyx settings from the home screen.
2. Use the “Disposition” button at the top of the Nyx settings.
3. Choose “Tuiles” or “Carrousel”.
4. Use “Save and reload” to apply the choice.

Closing the selector without saving keeps the previous layout.
The choice is stored in the `[config]` section of `bootloader/nyx.ini`:

```ini
home_layout=0
```

`0` selects the tiles and `1` the carousel. A missing or invalid setting
uses the tiles. The existing `homescreen` setting remains independent:
to display the home screen at startup, choose “Main menu” in “Home Screen”.

## The two modes

**Tuiles** (Tiles): a large launch command and four accesses to the additional
configs, payloads, emuMMC management and Diagnostic.

**Carrousel** (Carousel): cards move within a horizontal area. The arrows
or a visible card change the selection; “Ouvrir” (Open) launches only the
chosen function. A selection never launches a payload automatically.
The mode does not promise direct navigation with the directional pad:
the Joy-Con keep the pointer behaviour already present in Nyx.

Both modes use native shapes and fonts, with no additional images
to place on the SD card. The French labels of the sources
use ASCII compatible with the embedded fonts.

## Saving and diagnostic

The selector checks that Nyx is present before reloading. A save
error must display a message and prevent the reload. Errors in
writing and closing the configuration file are now taken
into account by the Nyx configuration writer.

The home screen theme is also applied to the components of the menus and
submenus: windows, panels, buttons, lists, settings, selectors,
switches, dialog boxes and tab bar. The alert colours
and the fixed-width numeric texts are kept. The custom backgrounds and tints
remain taken into account. The default theme uses the background
141A19, the panels 202B27, the accent 93E1AE and rounded corners.

Diagnostic now contains the whole table of HWTest probes, the export
and the RAM service with return to Hekate. See DIAGNOSTIC-INTEGRATION.md.

## Validation and limits

The complete build succeeded on 4 November 2026 with devkitARM GCC 16.1.0.
Hekate, Nyx and the modules were generated. The payload and uncompressed

For hardware validation, check the two layouts on the 1280 × 720 screen,
