# Nova27 — адаптация Bluetooth-хоста GUI из HWTest-RCM

`74b66aab2352ae35912744fcd5441b07a0146307`, проверен 2026-11-13.

Текущие `probe_bt.c` и `probe_wifi.c` совпадают с существующими исходниками диагностики
Nova после нормализации окончаний строк. Ранее упущенный хост GUI является
соответствующей дополнительной ссылкой. Он поддерживает один контроллер и выполняет
сопряжение. Nova сохраняет свою двухсобеседниковую службу BTstack, импортированные ключи и уровень
безопасности 2; его процедура сопряжения не заменяется.

Заметки об оборудовании в эталоне сообщают о потерянных входах размера EDR с ROM радио,
отключениях, связанных со sniff, и разрывах перезапуска UART, превышающих 300 мкс. Его код
выбирает пакеты базовой скорости, изначально разрешает смену роли/sniff, запрашивает
QoS с низкой задержкой и возвращает sniff-связи в активный режим. Цикл приёма допускает
2 мс тишины с лимитом вызова 8 мс и уровнем заполнения FIFO в 8 байт. Его запуск включает
LDO1/LDO7 и выходы опорной частоты PMIC. Эти факты направляют перенос в Nova.

Nova27 выражает этот профиль через существующие API BTstack и небольшой планировщик
ожидающих команд. Типы BR выбираются для исходящих вызовов и запрашиваются снова
для каждой установленной связи, включая входящие. Полученные события типа пакета и режима
регистрируются отдельно от отправки команд. Параметры QoS следуют
эталону. Никакая проприетарная прошивка или новое сопряжение не вводятся.

Насос приёма Nova дополнительно немедленно возвращает управление на изначально пустой строке
и имеет ограничение 2048 байт. Служба двух контроллеров сохраняет исправление перекрёстного HID
v26. Настройки напряжения салазок сохранены; демонтаж восстанавливает только собственные
биты управления PMIC и предыдущий уровень сброса Wi-Fi, без записей в PH0.

Новые тесты моделируют документированную потерю входа EDR и временные паузы UART. Реальный
стек v26 не проходит эти регрессии; v27 получает полные отчёты, применяет BR/QoS,
обрабатывает восстановление sniff и читает через паузы в 700 мкс. Проверяются бюджет насоса
в 8 мс и метаданные конфигурации нескольких команд. Тесты регистров платформы покрывают
уже включённые питания/часы, восстановление и несвязанные изменения битов PMIC.
Эти тесты на ПК подменяют оборудование; ни они, ни стендовые результаты upstream
не устанавливают успешную работу на консоли пользователя.

JSON аудита записывает хеши файлов upstream и результат сравнения. Исходник GUI
upstream служит ссылкой, а не упаковывается как неизменённый второй backend.
Существующие уведомления BTstack и HWTest остаются в проекте.
